## 1. 项目定位

| 项 | 内容 |
|---|---|
| 模块名 | 兵棋作战模块（battle） |
| 归属 | 主游戏「暗耻三国志」根目录下独立文件夹 |

## 4. 地图规格

| 项 | 决定 |
|---|---|
| 格子形状 | 平顶六边形（flat-top） |
| 默认尺寸 | **400 × 300 = 12 万格**（可调，写入地图 JSON） |
| 前期地形 | 无（全部同质） |
| 中期地形 | 引入地形类型（平原 / 山地 / 河流…） |
| 后期表现 | 升级为 2.5D（俯视 + 高度偏移） |
| 地图文件 | 单个 JSON，启动时加载 |
| 地图大小可改 | 通过 JSON 顶层字段修改，不改代码 |
| 地图与数据解耦 | 地图文件不绑定特定双方数据；数据文件不绑定特定地图 |

### 4.1 地图 JSON 结构

顶层字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | int | 版本号 |
| `id` | str | 地图 id |
| `name` | str | 显示名 |
| `cols` | int | 列数（默认 400） |
| `rows` | int | 行数（默认 300） |
| `hex_size` | int | 外接圆半径（像素） |
| `orientation` | str | `flat` |
| `tiles` | list | 步骤01 写 `[]`（显式空）；加载端容错字段缺失（缺失 = 全同质） |

### 4.2 平顶六宫格几何

| 参数 | 含义 |
|---|---|
| `HEX_SIZE` | 外接圆半径（像素），初值 24–32，写入配置 |
| 宽 | `2 * HEX_SIZE` |
| 高 | `√3 * HEX_SIZE` |
| 水平间距 | `1.5 * HEX_SIZE` |
| 垂直间距 | `√3 * HEX_SIZE` |

### 4.3 性能约束

| 约束 | 说明 |
|---|---|
| 禁止全图绘制 | 每帧只绘制当前视口内的格子 |
| 禁止全图遍历 | 模拟层不遍历 12 万格；只遍历部队列表 |
| 部队层视口裁剪 | 部队层只遍历视口覆盖的轴向坐标范围内的单位，不遍历全表 |
| 空间索引 | 空间哈希（格子 = 六角格尺寸），只查部队周围 1–2 圈 |
| 视口裁剪 | 部队符号按视口裁剪后绘制 |
| 脏标记 | 相机不动时不重绘静态层 |

## 5. 坐标系

| 用途 | 坐标 |
|---|---|
| 存储（JSON / 数据结构） | odd-q 偏移坐标 `(col, row)` |
| 内部计算（距离 / 邻居 / 路径） | 轴向坐标 `(q, r)` |
| 渲染 | 世界像素坐标 `(x, y)` |
| 屏幕 | 世界坐标经相机变换 |

`core/hexgrid.py` 提供：

| 函数 | 作用 |
|---|---|
| `offset_to_axial(col, row)` | 存储 → 计算 |
| `axial_to_offset(q, r)` | 计算 → 存储 |
| `axial_to_world(q, r)` | 计算 → 世界像素 |
| `world_to_axial(x, y)` | 世界像素 → 计算（鼠标拾取用） |
| `distance(a, b)` | 轴向距离 |
| `neighbors(q, r)` | 6 邻居 |
| `ring(q, r, n)` | 半径 n 的环（攻击范围用） |

## 6. 时间模型

| 项 | 决定 |
|---|---|
| 单位 | 毫秒 |
| 默认值 | 100 ms / tick（写入配置） |
| 驱动 | pygame 主循环内累计时间，达到 tick 长度推进一次模拟 |
| 暂停 | 随时可暂停；暂停时不推进模拟，仍渲染 |
| 渲染帧率 | 独立于 tick，默认 60 FPS |
| 行动顺序 | 同一 tick 内敌我双方同时计算意图，统一结算 |
| 速度控制 | 1x / 2x / 4x，改 tick 长度（100 / 50 / 25 ms） |
| 单步执行 | 调试模式下支持，按键推进一步 tick |

## 7. 部队数据模型

一个部队 = 一个棋子。字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | 唯一标识 |
| `side` | str | `red` / `blue` |
| `type` | str | 兵种 key |
| `troops` | int | 当前兵力，归 0 消亡 |
| `troops_max` | int | 兵力上限，查兵种表 |
| `morale` | float | 士气 1–100，归 0 溃散 |
| `stamina` | float | 体力 1–100 |
| `move_points` | int | 每 tick 可移动格数 |
| `attack` | int | 攻击力（基础 + 兵种加成） |
| `defense` | int | 防御力（基础 + 兵种加成） |
| `attack_range` | int | 攻击范围（1 = 近程；≥2 = 远程） |
| `attack_cooldown` | int | 攻击冷却（tick），查兵种表 |
| `cooldown_left` | int | 剩余冷却 tick |
| `q`, `r` | int | 轴向坐标 |
| `facing` | int | 朝向 0–5，预留，前期不消费 |
| `alive` | bool | 是否存活 |
| `death_reason` | str \| None | `killed` / `routed`，预留 |
| `command` | Command \| None | 当前命令 |
| `general_id` | str \| None | 将领 id，预留，前期不起作用 |

数值上限 / 缺省值一律查兵种表，不在单位上硬编码。

**只读派生属性**（不落盘，查兵种表）：`troops_max` / `move_points` / `attack` / `defense` / `attack_range` / `attack_cooldown`。

**JSON 只存**：`id` / `side` / `type` / `col` / `row`（偏移坐标） / `troops` / `morale` / `stamina` / `facing` / `general_id`；加载时 `col/row` 经 `hexgrid.offset_to_axial` 转成内部 `q/r`。详情见 `battle/docs/步骤02需求.md` §3.3。

三类十种：

| 类别 | 兵种 |

| 骑兵类 | 具装甲骑 / 重骑 / 轻骑 / 弓骑 |
| 步兵类 | 重甲 / 甲士 / 甲兵 / 徒卒 |
| 弓兵类 | 弩士 / 步弓 |

每个兵种一条记录：

| 字段 | 说明 |
|---|---|

| `troops_max` | 兵力上限 |
| `move_points` | 每 tick 移动格数 |
| `attack_melee` | 近程攻击力 |
| `attack_ranged` | 远程攻击力（无远程则 None） |
| `attack_range` | 1 = 仅近程；≥2 = 可远程 |
| `defense` | 基础防御力 |
| `stamina_cost_move` | 每格移动消耗体力 |
| `stamina_cost_attack` | 攻击消耗体力（每次攻击开始扣一次） |
| `stamina_recover` | 静止每 tick 恢复体力 |
| `morale_recover` | 静止每 tick 恢复士气 |
| `attack_cooldown` | 攻击冷却 tick |

| `morale_kill` | 击杀目标士气恢复 |

具体数值与填充模式取值见 `battle/docs/步骤02需求.md` §3.4 / §3.5。改平衡只改这一处。

克制关系（前期定义，可暂不消费）：

| 形式 | 说明 |
|---|---|
| `COUNTER_MATRIX[攻方类别][守方类别] = 倍率` | 3×3 矩阵，默认 1.0 |

平衡数值全部集中在 `balance.py`，改平衡只改一处。

| 项 | 决定 |
|---|---|

## 10. 战斗规则

### 10.1 移动

- 模拟层格级离散：每个 tick 沿 A* 路径推进 `move_points` 格。
- 渲染层视觉插值：每帧平滑逼近模拟位置，速度与 tick 长度成比例。
- 路径避让：每个部队独立 A*，代价函数把「其他部队当前格」设为高代价（非禁行）。
- 框选移动：各自规划路径，不编队。
- 一格子一部队，不能重叠。
- 同 tick 抢占同一格：按部队 id 升序，先到先得；未抢到者本 tick 停在原地，下一 tick 重新规划。

### 10.2 攻击

- 接触规则：自动交战，根据命令与当前态势判断。撤退命令下无视敌人。
- 近程攻击：相邻格。
- 远程攻击：距离 ≥ 2 格；有最小射程（相邻格只能近程）；无视线要求。
- 持续结算：攻击开始后每 tick 扣一次伤害，直到目标消亡或攻击方中断。
- 冷却：攻击后进入冷却，时长查兵种表；冷却期间不能攻击，仍可移动 / 待命。
- 伤害公式：`伤害 = max(1, (攻击力 × 克制倍率 - 防御力 × 0.5) × 随机(0.9~1.1))`，每 tick 结算。
- 命中判定：基础命中 90%，按攻防比修正 ±5%。
- 暴击：5% 概率，伤害 ×1.5，不叠加其他倍率。
- 随机种子写入配置，调试时可固定复现。

### 10.3 士气

| 触发 | 变化 |
|---|---|
| 被攻击 | 每 tick -1；单 tick 兵力损失 > 当前兵力 10% 时额外 -5 |
| 攻击造成伤害 > 目标兵力 10% | 攻击方 +2 |
| 击杀目标 | 攻击方 +10 |
| 目标溃散 | 攻击方 +5 |
| 附近 3 格内己方消灭敌人 | +5（范围与数值放配置） |
| 静止 | 每 tick +morale_recover（按兵种） |
| 士气归 0 | 溃散（前期 = 从战场移除，death_reason = routed） |

### 10.4 体力

| 触发 | 变化 |
|---|---|
| 移动 | 每格消耗 `stamina_cost_move` |
| 攻击 | 每次攻击开始扣 `stamina_cost_attack` |
| 静止 | 每 tick 恢复 `stamina_recover` |
| 归 0 | 不影响消亡；影响能力（具体系数放配置） |

### 10.5 被包围惩罚

- 目标相邻格敌方部队数 ≥ 3 → 防御力 × 0.7。
- ≥ 5 → 防御力 × 0.5。
- 阈值放配置。

### 10.6 多单位协同

- 多己方攻击同一目标：伤害分别结算，不合并。
- 被包围惩罚独立计算。

### 10.7 攻击中断

- 收到移动 / 撤退命令 → 立即中断攻击，下一 tick 开始移动。
- 主动停止：下达「停止」命令。
- 被攻击方撤退：下一 tick 开始脱离；攻击方若开启自动追击则跟进，否则停在原地。

### 10.8 消亡与溃散

| 原因 | 条件 | 处理 |
|---|---|---|
| `killed` | 兵力归 0 | 从战场移除，格子立即释放，不留尸体（渲染层可做 0.5 秒淡出） |
| `routed` | 士气归 0 | 同上，前期不区分视觉表现 |

结算画面分开统计「被歼灭」与「溃散」数量。

## 12. 渲染规格

### 12.1 视口与缩放

| 项 | 决定 |
|---|---|
| 窗口 | pygame 独立窗口，可调大小 |
| 默认缩放 | 1600×1300 显示器下显示约 40×32 格（每格约 40px） |
| 缩放范围 | 最小：整张地图占屏幕 1/2；最大：单格 200px |
| 相机 | 支持平移 / 缩放；只绘制视口内格子 |
| 世界坐标 | 浮点；格坐标整数 |

### 12.2 LOD 分级

「屏幕上的格边长」= `camera.zoom * HEX_SIZE`（像素）。

| 级别 | 阈值（写入 `config.py`） | 显示内容 | 用途 |
|---|---|---|---|
| 远 | 格边长 < `LOD_FAR_MAX_PX`（建议 12） | 小色块（边长 `LOD_FAR_SIZE_PX`，建议 6px，颜色 = `SIDE_COLOR[side]`）；**不显示**外形 / 小字 / 数值 / 小条 | 全局态势 |
| 中 | `LOD_FAR_MAX_PX` ≤ 格边长 < `LOD_NEAR_MIN_PX`（建议 28） | 完整兵棋符号 + 兵种小字 + 士气 / 体力小条 | 主要操作视角 |
| 近 | 格边长 ≥ `LOD_NEAR_MIN_PX` | 完整兵棋符号 + 兵种小字 + 士气 / 体力小条 + **兵力数字** | 精细查看 |

- 三个级别。
- 切换阈值写入配置，运行时可调。
- 远视角不聚合，几百个部队符号允许重叠。

## 14. 存档与热重载

### 14.1 战斗存档

- 支持中途存档到 `battle/saves/`，JSON 格式。
- 内容：tick 计数、双方部队完整状态、随机种子。
- 读取存档可继续战斗。
- 命名：`save_YYYYMMDD_HHMMSS.json`，保留最近 N 个（配置）。
- 独立运行时可用；接入主游戏后可选（配置开关）。

### 14.2 配置热重载

- 支持 F5 重载配置。
- 立即生效：兵种数值 / 克制矩阵 / 颜色 / 显示开关；已加载部队重新计算派生值。
- 需重启：地图尺寸 / 坐标系统 / 数据结构。
- 重载失败：保留旧配置 + 终端 + 弹窗提示。

## 15. 日志与错误处理

| 项 | 决定 |
|---|---|
| 日志系统 | 复用 `shared.logging_setup`（项目根 `shared/` 包，单一定义源） |
| 独立运行 | 直接 `from shared.logging_setup import setup_logging, install_sys_excepthook`；`import` 失败时降级为 Python 标准 `logging.basicConfig`，格式与主游戏一致 |
| 启动顺序 | `setup_logging()` → `install_sys_excepthook()` → `pygame.init()` + 建窗口（**不调** `install_tk_excepthook`） |
| session id / 格式 / 保留数量 / LOG_ENABLED | 全部沿用 `shared.logging_setup`（等价于原主游戏行为） |
| logger 命名 | `logging.getLogger("battle.xxx")`，便于在主游戏日志中过滤 |
| 异常：数据字段缺失 | 跳过该项 + WARNING + 终端 print + 弹窗 |
| 异常：地图文件损坏 | 启动失败 + ERROR + 弹窗 + 退出 |
| 异常：运行时逻辑异常 | ERROR + traceback 入日志，尝试继续运行 |

## 21. 架构可持续性关键点

| 点 | 说明 |
|---|---|
| 数据层与渲染层分离 | `core/` / `sim/` 无 pygame；`render/` 只读 |
| 模拟与视觉分离 | 模拟格级离散；渲染插值平滑 |
| UI 与地图解耦 | 地图画布不感知 `BattleState` / `Unit`；选中集 / 面板状态由 `app.py` 持有 |
| 配置集中 | `config.py`（结构）+ `balance.py`（数值） |
| 接口预留 | `api.py` 不依赖 pygame，`BattleSession` / `BattleConfig` / `BattleResult` |
| 字段预留 | `facing` / `general_id` / `death_reason` / `command` 队列 |
| 地图与数据解耦 | 地图 JSON 不绑定部队数据 |
| 文档先行 | 每步文档齐备后才进入编码 |
| 日志共享 | 单一定义源在 `shared/logging_setup.py`，跨模块复用 |
