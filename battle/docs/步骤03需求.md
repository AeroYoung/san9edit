## 1. 背景问题

步骤01、02 已完成：地图渲染、相机、部队数据模型、兵种表、兵棋符号、面板组、控制台、单击 / 框选。当前状态：

- 没有时间推进 —— 地图上的棋子是静态数据。
- 没有命令系统 —— 无法下达任何指令。
- `sim/` 层只有目录占位，`clock.py` / `command.py` / `pathfinding.py` / `step.py` / `spatial.py` 等尚未落地（见 `模块说明.md` §2「尚未存在」清单）。
- 控制台只有「进行 / 暂停」按钮骨架，无速度档、无单步。

因此需要先打通「时间 → 命令 → 移动」这条最小链路，让棋子能按玩家指令在地图上动起来，为步骤04（攻击结算）提供运动基础。

## 2. 需求目标

| 编号 | 目标 |
|---|---|
| G1 | 落地 tick 时间模型：暂停 / 继续、速度档 1x / 2x / 4x、单步执行 |
| G2 | 落地命令系统骨架：抽象 `Command` + `MoveCommand`（其余命令子类留待后续步骤） |
| G3 | 落地移动执行：A* 寻路、每 tick 推进、占位冲突结算、到达后清空命令 |
| G4 | 落地路径预览与视觉插值：选中部队路径虚线、棋子帧间平滑移动 |
| G5 | 控制台与面板增量：单步按钮、速度档、部队面板「当前命令」列可读 |

## 3. 规则细节

### 3.1 时钟与 tick

| 项 | 规则 |
|---|---|
| 时间单位 | 毫秒 |
| tick 长度 | 默认 100 ms；速度档 = 100 / 50 / 25 ms（1x / 2x / 4x） |
| 时钟载体 | `sim/clock.py` 中的 `Clock` 类，持有：累计时间、当前 tick 长度、暂停位、当前速度档 |
| 暂停语义 | 暂停期间**不累加**时间；恢复后**不补跑**（不一次性补齐暂停期间的时间） |
| 速度切换 | 立即生效；切换时**清零当前累计时间**（不把旧档位累计带入新档位） |
| 推进判定 | 主循环每帧把真实 elapsed 时间交给时钟累计；累计 ≥ 当前 tick 长度 → 推进一次模拟并扣除一个 tick 长度（一帧可推进多次，防止卡帧丢 tick） |
| 单步执行 | **仅暂停态可用**；未暂停时点单步 = 先自动暂停，再推进一个 tick |
| 渲染帧率 | 独立于 tick，默认 60 FPS；暂停时不推进模拟但**继续渲染** |
| tick 计数 | `BattleState` 增加 `tick: int` 字段，每推进一次 +1，初始 0 |
| 随机种子 | `BattleState` 增加 `seed` 字段**占位**，本步不消费（为步骤04 战斗随机与 §14.1 存档预留） |

### 3.2 命令模型

| 项 | 规则 |
|---|---|
| 基类 | `sim/command.py` 中定义抽象 `Command`。**不做 undo / redo**（战斗模块无编辑会话概念） |
| 子类 | 本步只实现 `MoveCommand`；攻击 / 待命 / 撤退 / 停止留待后续步骤 |
| `Command` 接口 | 必须提供 `label() -> str`（战斗模块自用，供控制台 / 面板显示命令文本）；不引入与主游戏 EditSession 相关的任何接口 |
| `MoveCommand` 字段 | `target: (q, r)`（目标格，轴向坐标）+ `path: list[(q, r)]`（当前路径，不含起点格） |
| 不建的字段 | 遇敌策略、自动追击、路径偏好 —— 本步**不建**（见 §4.2 YAGNI 说明） |
| 路径存放 | 存在 `Unit.command.path`，不在 `BattleState` 上另开映射 |
| 多选下达 | N 个部队各造一个独立 `MoveCommand`，各自独立 A*；不共享命令对象 |
| 命令覆盖 | 新命令立即覆盖旧命令，下一 tick 生效（整体需求 §9） |
| 命令清除 | 部队到达 `target` → `unit.command = None`（视为已完成） |

### 3.3 寻路

| 项 | 规则 |
|---|---|
| 文件 | 新建 `sim/pathfinding.py`；`sim/spatial.py` 只负责空间哈希查询，不承担寻路 |
| 形态 | 纯函数 `find_path(state, unit, target) -> list[(q, r)]`（不含起点格；不可达返回空列表或约定的失败值） |
| 算法 | A*（整体需求 §10.1） |
| 代价函数 | 每格基础代价相同；「其他部队当前所在格」设为**高代价非禁行**（整体需求 §10.1「路径避让」），保证有解 |
| 坐标 | 全程轴向坐标 `(q, r)`；坐标换算一律走 `core/hexgrid.py`，本模块不得自写坐标公式 |
| 重算时机 | 下令时算一次；移动中若下一格被占 → 本 tick 停 + **下一 tick 从当前位置重算到原 `target`**（保留 `target`） |
| 目标格被占 | 允许下令（不拦）；到达冲突按 §3.4 处理 |

### 3.4 占位与抢格

| 项 | 规则 |
|---|---|
| 基础约束 | 一格一部队，不能重叠 |
| 同一 tick 结算顺序 | 先各部队算意图，再**统一结算**；结算顺序 = 抢格优先级 |
| 抢格优先级 | **兵种优先级 → 同兵种内部队 id 升序**；优先级高者先占 |
| 优先级来源 | `balance.py` 兵种表每条增加 `collision_priority: int` 字段，**越小越优先**，取值 1–10 |
| 十兵种优先级序（高→低） | 具装甲骑 1 ＞ 重骑 2 ＞ 轻骑 3 ＞ 弓骑 4 ＞ 重甲 5 ＞ 甲士 6 ＞ 甲兵 7 ＞ 徒卒 8 ＞ 弩士 9 ＞ 步弓 10 |
| 未抢到者 | 本 tick 停在原地，下一 tick 重新规划 |
| 单 tick 多格推进 | **逐格推进并逐格判占位**：本 tick 内第 1 格被抢 → 停原地；之后第 k 格被抢 → 停在上一格 |
| 多部队同目标格 | 下令时全部接受，不拦；到达冲突时先到者占格；后到者停在路径上距目标最近的**空邻格**，命令视为已完成；若连相邻空格都没有 → 停原地，命令结束 |

### 3.5 移动执行

| 项 | 规则 |
|---|---|
| 每 tick 推进量 | 沿路径推进 `move_points` 格（查兵种表，见整体需求 §7） |
| 执行顺序 | 与整体需求 §6 一致：同一 tick 内同时算意图、统一结算 |
| 命令覆盖 | 移动途中收到新命令 → 下一 tick 按新命令执行（本步只有移动命令，故为改道） |
| 攻击中断等 | 本步不涉及（无攻击） |
| 到达 | 抵达 `target` → 清空命令（§3.2） |

### 3.6 视觉插值

| 项 | 规则 |
|---|---|
| 是否做 | **本步做**（否则棋子逐格瞬移，肉眼似卡顿） |
| 接口口径 | 渲染层**只读** `Unit.q/r` + 「本 tick 内的插值进度」（0.0–1.0）；渲染层不写 `Unit` 任何字段（模块说明 §3 硬约束 2） |
| 进度来源 | 由时钟提供（当前帧在 tick 内的进度）；具体命名由编码决定 |
| 与 LOD 关系 | 三级 LOD 规则（整体需求 §12.2）不变，插值只影响位置，不影响显示级别 |

### 3.7 UI 交互（本步增量）

| 项 | 规则 |
|---|---|
| 下达移动 | 选中（或框选）→ **右键菜单「移动」**，或 **控制台「移动」按钮**（两者等价）→ 进入「目标格选择态」→ 点地图一格 → 生成命令 |
| 目标格选择态 | 鼠标指示进入可点选状态；点空白 / 非格区域取消；Esc 取消 |
| 路径预览 | **只画选中部队的路径**（单选或框选中的那批），未选中的部队不画；有 `command.path` 时画虚线；选中但未下令不画。**不引入总开关**（只画选中，天然不会乱） |
| 右键菜单 | 只放「移动」一项；**不显示**遇敌策略 / 自动追击 / 路径偏好等子菜单项（本步无战斗，选了无用） |
| 控制台新增按钮 | 「单步」（暂停态可点；未暂停时点击 = 先自动暂停再走一步）+ 速度档「1x / 2x / 4x」三选一 |
| 部队面板「当前命令」列 | 显示命令文本，取值走 `Command.label()`（如「移动 → (12, 8)」）；无命令显示空或「—」 |
| 敌方部队 | **完全静止**：不下命令、不移动、不攻击；玩家只操纵 `PLAYER_SIDE` 一方 |

| 日志 | 复用 `shared.logging_setup`；logger 命名 `battle.xxx`；`LOG_ENABLED` 不新增判断点 |

### 4.2 YAGNI 说明（必须写入文档，后续步骤须回看）

`MoveCommand` 本步**不建**遇敌策略 / 自动追击 / 路径偏好字段，因为本步没有战斗、没有敌人，建了就是死字段。

> ★ **待更新提醒**：步骤04 引入攻击与地形后，必须回头更新本节与 §3.2 的 `MoveCommand` 字段表，并同步 §9.1 的右键子菜单（遇敌：无视 / 停下 / 交战；自动追击：开 / 关；路径：最短 / 避敌）。编码到此步时**主动提醒用户**。

### 4.3 已知限制（本步接受）

| 项 | 说明 |
|---|---|
| 无地形代价 | 所有格同质，A* 只对「被占格」加高代价 |
| 敌方静止 | 无 AI，敌方不响应 |
| 无碰撞体积动画 | 抢格在模拟层解决，渲染层只做位置插值，不做挤压 / 绕行动画 |
| 命令不可队列 | 新命令直接覆盖（整体需求 §9「前期不做命令队列」） |
| 路径不共享 | 多部队同目标格各算各的路径，不做合流 |

## 5. 不要做的事

1. **不做**攻击 / 近程远程判定 / 攻击冷却 / 伤害结算。
2. **不做**士气与体力的数值变化（本步只保留字段，不消费）。
3. **不做**被包围惩罚 / 多单位协同 / 攻击中断。
4. **不做**溃散与消亡（`death_reason` 不写入）。
5. **不做**撤退 / 待命 / 停止命令（命令子类只做 `MoveCommand`）。
6. **不做**路径避敌 / 自动追击 / 遇敌策略（字段与菜单都不出现）。
7. **不做**命令队列。
8. **不做** AI（敌方完全静止）。
9. **不做**胜负判定 / 结算画面 / `battle_result.json` 输出。
10. **不做**战斗存档 / 配置热重载。
11. **不做**地形、克制矩阵消费、`COUNTER_MATRIX` 任何读取。
12. **不做** `api.py` 的 `BattleSession` 实现（仍为预留）。
13. **不在** `sim/` / `core/` 中 import pygame；**不**让 `render/` 写 `Unit` / `BattleState` 字段。
14. **不**在 `core/hexgrid.py` 之外自写坐标换算公式。

## 6. 约束

以下为既有约定，本步不得违反（来源见括号）：

| 约束 | 内容 |
|---|---|
| 分层 | `sim/` 允许标准库 + `core/` + `config` / `balance`；禁止 pygame / `render/` / `ai/` / `app`（`模块说明.md` §3） |
| core 与 sim 无 pygame | 保证逻辑层可脱离图形单测（`模块说明.md` §3 硬约束 1） |
| render 只读 | 不写 `Unit` / `BattleState` 字段，不调 `sim/` 推进函数（`模块说明.md` §3 硬约束 2） |
| 坐标 | 存储 odd-q `(col,row)`；计算轴向 `(q,r)`；换算只走 `core/hexgrid.py`（`模块说明.md` §5） |
| 性能 | 禁止全图绘制 / 全图遍历；只遍历部队列表；空间索引只查部队周围 1–2 圈（`整体需求.md` §4.3） |
| 配置集中 | 结构配置进 `config.py`，数值 / 兵种表进 `balance.py`；改平衡只改一处（`模块说明.md` §7、`整体需求.md` §8） |
| 不硬编码数值 | 数值上限 / 缺省一律查兵种表；`collision_priority` 也在兵种表内 |
| 日志 | 只用 `shared.logging_setup`；logger 名 `battle.xxx`；不调 `install_tk_excepthook`；import 失败降级为标准 `logging.basicConfig`（`模块说明.md` §6.3） |
| UI 与地图解耦 | 地图画布不感知 `BattleState` / `Unit`；选中集 / 面板状态由 `app.py` 持有（`整体需求.md` §21） |
| 时间模型 | 暂停不推进模拟但仍渲染；渲染帧率独立于 tick（`整体需求.md` §6） |

## 7. 验收清单

**时钟**

- [ ] 启动后模拟自动按 100 ms / tick 推进，渲染稳定 60 FPS
- [ ] 点「暂停」后模拟停止推进，画面仍持续渲染
- [ ] 暂停后点「继续」恢复推进；暂停期间的时间**不补跑**
- [ ] 速度档 1x / 2x / 4x 可切换，切换立即生效且不产生补跑
- [ ] 「单步」在暂停态点击推进恰好 1 个 tick；未暂停时点击自动先暂停再走 1 步
- [ ] `BattleState.tick` 随每次推进 +1

**命令与寻路**

- [ ] 选中一个部队 → 右键「移动」或控制台「移动」→ 进入目标格选择态 → 点地图一格 → 生成 `MoveCommand`
- [ ] 点目标格后棋子沿路径逐格移动，路径避开其他部队所在格（高代价绕行）
- [ ] 框选 N 个部队下达同一目标格 → 各部队独立寻路、各自移动
- [ ] 到达目标格的部队 `command` 被清空
- [ ] 目标格不可达时给出可见反馈（不静默）

**占位冲突**

- [ ] 多部队同 tick 竞争同一格时，按 `collision_priority` → 同兵种 id 升序决定归属
- [ ] `balance.py` 十兵种均有 `collision_priority`，取值符合 1–10 序
- [ ] 未抢到格的部队本 tick 停原地，下一 tick 继续
- [ ] 单 tick 内推进多格时逐格判定，遇占停在前一格
- [ ] 多部队同目标格时，先到者占格，后到者停在最近空邻格并结束命令

**渲染**

- [ ] 选中部队的路径以虚线显示；未选中部队不显示路径
- [ ] 路径随每 tick 重算实时更新（仅选中部队）
- [ ] 棋子帧间平滑移动，无逐格瞬移观感
- [ ] 三级 LOD 行为与步骤02 一致，未被本步破坏

**UI**

- [ ] 控制台出现「单步」按钮与速度档，行为符合上文
- [ ] 部队面板「当前命令」列显示移动命令文本，到达后变空
- [ ] 敌方部队全程静止
- [ ] 右键菜单只有「移动」，无遇敌 / 追击 / 路径子菜单

**约束**

- [ ] `sim/` 与 `core/` 中无 pygame import
- [ ] `render/` 未写任何 `Unit` / `BattleState` 字段
- [ ] 坐标换算全部走 `core/hexgrid.py`
- [ ] 日志走 `shared.logging_setup`，logger 前缀 `battle.`
