# 兵棋作战模块 · 模块说明

本文档描述**战斗模块（battle）的定位、边界、目录结构、分层约定与当前状态**。
需求细节以 `battle/docs/整体需求.md` 与 `battle/docs/步骤NN需求.md` 为准；本文档只回答「这是什么、怎么放、谁依赖谁」。

---

## 1. 模块定位

| 项 | 内容 |
|---|---|
| 模块名 | 兵棋作战模块（battle） |
| 归属 | 主游戏「暗耻三国志」根目录下独立文件夹 |
| 层 | 战术层；主游戏为回合制战略层，本模块为实时制战术层 |
| 运行方式 | 开发期可单独运行（`python -m battle`）；后期接入主游戏作为独立窗口 |
| 玩法参照 | 常见兵棋作战游戏（实时推进 + 随时暂停下令 + 兵棋符号） |
| 本模块不负责 | 战略地图 / 内政 / 外交 / 存档 / 剧本编辑（属主游戏其他模块） |
| 主游戏耦合 | 仅日志系统（见 §6）；其余不依赖 |

## 3. 分层约定

依赖方向单向：

```text
app.py ──┬─→ render/ ──→ core/
         ├─→ sim/    ──→ core/
         ├─→ ai/     ──→ core/ + sim/
         └─→ core/
```

| 层 | 允许 import | 禁止 import |
|---|---|---|
| `core/` | 标准库；`config` / `balance` | pygame、`sim/`、`render/`、`ai/`、`app` |
| `sim/` | 标准库；`core/`、`config` / `balance` | pygame、`render/`、`ai/`、`app` |
| `ai/` | 标准库；`core/`、`sim/`、`config` / `balance` | pygame、`render/`、`app` |
| `render/` | 标准库；`pygame`；`core/`（**只读**）、`config` / `balance` | `sim/`、`ai/`、`app` |
| `app.py` | 以上全部 + pygame | — |
| `api.py` | 标准库、`core/`、`config` / `balance` | pygame、`render/`、`app` |

三条硬约束：

1. **`core/` 与 `sim/` 不 import pygame** —— 保证逻辑层可单测、可脱离图形运行。
2. **`render/` 只读数据** —— 不写 `Unit` / `BattleState` 字段，不调 `sim/` 的推进函数。
3. **`api.py` 不依赖 pygame** —— 主游戏接入时不需要先初始化图形环境。

## 4. 运行方式

### 4.1 独立运行（开发期）

```bash
python -m battle              # 从项目根
python battle/__main__.py     # 任意 cwd
```

两种方式等价：入口会把项目根（`shared/` 与 `battle/` 的父目录）补进 `sys.path`。
所有路径以 `battle/` 根为基准由 `config.py` 反推，不依赖 cwd。

启动顺序：

```text
__main__.py
 └─ shared.logging_setup.setup_logging()      失败时降级为标准 logging
 └─ shared.logging_setup.install_sys_excepthook()
 └─ app.run()
     ├─ pygame.init() + 建窗口
     ├─ 载入 battle/assets/maps/default.json
     ├─ 建相机
     └─ 主循环：事件 → 更新相机 → 渲染 → flip
```

### 4.2 接入主游戏（后期）

主游戏调用 `battle/api.py` 的 `BattleSession` 类，传入 `BattleConfig`，返回 `BattleResult`。

- 主游戏侧不直接读 `World`，由主游戏侧组装 `BattleConfig` 后传入。
- 战斗时主窗口隐藏。
- 同一进程内可连续开多场，不支持并行。

## 5. 坐标系

| 用途 | 坐标 |
|---|---|
| 存储（JSON / 数据结构） | odd-q 偏移坐标 `(col, row)` |
| 内部计算（距离 / 邻居 / 路径） | 轴向坐标 `(q, r)` |
| 渲染 | 世界像素坐标 `(x, y)` |
| 屏幕 | 世界坐标经相机变换 |

转换全部由 `core/hexgrid.py` 提供，其余模块**不得**自行实现坐标公式。

## 6. 日志与跨模块共享

### 6.1 日志单一定义源

日志系统定义在 `shared/logging_setup.py`（项目根下 `shared/` 包），**不**属于任何单一模块：

- 自含 `PROJECT_ROOT`（`__file__.parent.parent` 反推）、`USER_DATA_DIR`、`LOG_DIR`、`LOG_ENABLED`、`_MAX_LOG_FILES`。
- 导出 `setup_logging` / `install_sys_excepthook` / `install_tk_excepthook` / `get_session_id` / `get_log_file_path`。
- **不得** import `game.*` / `battle.*`，避免循环依赖。

### 6.2 主游戏侧兼容

- `game/config/logging_setup.py` 保留为 re-export 薄壳（显式 re-export 对外符号）。
- `game/config/constants.py` 的 `LOG_DIR` / `LOG_ENABLED` 改为从 `shared.logging_setup` 导入。
- 主游戏其余代码**不改** import 路径，由薄壳兜住。

### 6.3 battle 侧接入

- 只用 `setup_logging()` + `install_sys_excepthook()`；**不调** `install_tk_excepthook`（pygame 无 tkinter）。
- logger 命名 `logging.getLogger("battle.xxx")`，便于在主游戏日志中按前缀过滤。
- `import shared.logging_setup` 失败 → 降级为标准 `logging.basicConfig`（格式保持一致），**不静默吞异常**。
- 日志格式、文件名、保留数量、session id 规则全部沿用主游戏约定（见主游戏 `README.md` §5.6）。

### 6.4 `LOG_ENABLED` 开关

编译期开关，只在 `shared/logging_setup.py` 里改。

| 值 | 行为 |
|---|---|
| `True` | 建目录 + 清旧 + 建新 + 挂 FileHandler + 装异常钩子 |
| `False` | `logging.disable(CRITICAL)`、不建目录、不清理、不挂 handler、不装钩子；未捕获异常交回 Python / Tk 默认 stderr |

## 7. 配置

### 7.1 `config.py`（结构配置）

窗口尺寸、FPS、tick 长度、速度档位、HEX_SIZE、颜色、字体路径、地图路径、随机种子、调试开关，
以及静态层绘制策略（视口外扩缓存 `CACHE_MARGIN_PX` / 低缩放合并阈值 `SOLID_FILL_CELL_LIMIT`）。

所有路径以 `battle/` 为基准，由 `config.py` 自身 `__file__` 反推，**不用 cwd**。

窗口尺寸超出桌面可用区域时，按 `pygame.display.get_desktop_sizes()` 夹取并居中 —— 否则窗口比
工作区还高时，标题栏（最小化 / 最大化 / 关闭）会被挤到屏幕外。

### 7.2 `balance.py`（数值配置）

兵种表、克制矩阵、士气 / 体力系数。改平衡只改这一处。

### 7.3 地图与数据解耦

- 地图 JSON（`assets/maps/*.json`）不绑定特定双方部队数据。
- 部队数据 JSON（`data/side_*.json`）不绑定特定地图。
- 地图尺寸（`cols` / `rows` / `hex_size`）改 JSON 即可生效，不改代码。
