## 1. 背景问题

| 现状 | 问题 |
|---|---|
| `battle/` 目录不存在 | 战斗模块无任何代码 |
| 日志系统位于 `game/config/logging_setup.py`，且 `from game.config.constants import LOG_DIR, LOG_ENABLED` 硬依赖主游戏常量 | 战斗模块若直接引用，等于把整个 `game/` 拖成依赖，违反「模块独立」定位 |
| 日志「编译期总开关」约定（`LOG_ENABLED`）写在主游戏 `constants.py` | 战斗模块无法单独启用/关闭日志 |

---

## 2. 需求目标

1. **日志模块抽离**：把日志实现从 `game/config/` 迁到项目根 `shared/logging_setup.py`，自含路径与开关，`battle/` 与 `game/` 均可独立引用。
2. **战斗模块骨架落地**：建 `battle/` 目录结构，`python -m battle` 可独立启动 pygame 窗口。
3. **地图与六宫格绘制**：加载 `battle/assets/maps/default.json`，渲染 400×300 平顶六宫格，支持拖拽平移 / 滚轮缩放。
4. **范围可控**：不含部队、模拟、AI、攻击、胜负、地形。

---

## 3. 规则细节

### 3.1 日志模块抽离

| 项 | 决定 |
|---|---|
| 新落点 | `shared/` 包（项目根下，与 `game/`、`battle/` 同级） |
| 新文件 | `shared/__init__.py`（空）、`shared/logging_setup.py`（自含单一定义源） |
| 路径反推 | `shared/logging_setup.py` 自身 `__file__.resolve().parent.parent` → `PROJECT_ROOT`；`USER_DATA_DIR = PROJECT_ROOT / "userdata"` |
| 常量归属 | `LOG_DIR`、`LOG_ENABLED`、`_MAX_LOG_FILES` 定义在 `shared/logging_setup.py`；**不再**从 `game.config.constants` 导入 |
| 对外符号 | `get_session_id` / `get_log_file_path` / `setup_logging` / `install_sys_excepthook` / `install_tk_excepthook`（tk hook 一并迁入，pygame 侧不调用） |
| 内部符号 | `_SESSION_ID` / `_LOG_FILE_PATH` / `_SessionFilter` / `_cleanup_old_logs` / `_MAX_LOG_FILES = 30` |
| 行为 | 与现有实现**逐条等价**：只挂 FileHandler、格式不变（`%(asctime)s.%(msecs)03d [%(levelname)-5s] [%(session)s] %(name)s: %(message)s`）、`LOG_ENABLED=False` 时 `logging.disable(CRITICAL)` + 返回 `None` + 不装钩子、重复初始化保护、`_cleanup_old_logs` 只保留 30 个 |

| 兼容层 | 决定 |
|---|---|
| `game/config/logging_setup.py` | 改为 **re-export 薄壳**，显式 re-export 上述 5 个对外符号（不用 `import *`，避免 `__all__` 缺失时丢符号） |
| `game/config/constants.py` | `LOG_DIR` / `LOG_ENABLED` 改为从 `shared.logging_setup` 导入；删除本地定义；`USER_DATA_DIR` 保留 |
| `main.py` / `game/ui/main_window.py` 等 | **本轮不改**，由薄壳兜住 |
| 循环导入 | `shared/logging_setup.py` **不得** import `game.*` / `battle.*`；`game.config.constants` 单向依赖 `shared` |

**「编译期开关只在 constants.py 改」的约定更新为**：只在 `shared/logging_setup.py` 里改。

### 3.4 `balance.py`（步骤01 骨架）

只放占位常量：`UNIT_TYPES = {}`、`COUNTER_MATRIX = {}`，加注释说明后续填充。步骤01 不消费。

### 3.5 地图 JSON（`assets/maps/default.json`）

顶层字段：

| 字段 | 类型 | 值 |
|---|---|---|
| `version` | int | 1 |
| `id` | str | `"default"` |
| `name` | str | `"默认地图"` |
| `cols` | int | 400 |
| `rows` | int | 300 |
| `hex_size` | int | 28（或与 `config.HEX_SIZE` 一致） |
| `orientation` | str | `"flat"` |
| `tiles` | list | `[]`（显式空） |

加载端**必须**同时容错 `tiles` 字段缺失（缺失 = 全同质）。

改 `cols` / `rows` / `hex_size` 后**不改代码**即可生效。

### 3.6 `core/map_data.py`

| 输入 | 输出 |
|---|---|
| `default.json` 路径 | 一个地图数据容器（字段 = 上述 8 个顶层字段） |

约束：

- 不 import pygame。
- 文件不存在 / JSON 损坏 → 抛异常，由 `app.py` 捕获后 ERROR + 弹窗 + 退出。
- 字段类型不符（如 `cols` 是字符串）→ 尝试 `int()` 转换；仍失败 → 报错退出。

### 3.7 `core/hexgrid.py` 函数清单（全部实现）

| 函数 | 作用 |
|---|---|
| `offset_to_axial(col, row)` | odd-q 偏移 → 轴向 |
| `axial_to_offset(q, r)` | 轴向 → odd-q 偏移 |
| `axial_to_world(q, r)` | 轴向 → 世界像素（平顶） |
| `world_to_axial(x, y)` | 世界像素 → 轴向（鼠标拾取用） |
| `distance(a, b)` | 轴向距离 |
| `neighbors(q, r)` | 6 邻居 |
| `ring(q, r, n)` | 半径 n 的环 |

几何公式（与需求 §4.2 一致）：

| 参数 | 值 |
|---|---|
| 宽 | `2 * HEX_SIZE` |
| 高 | `√3 * HEX_SIZE` |
| 水平间距 | `1.5 * HEX_SIZE` |
| 垂直间距 | `√3 * HEX_SIZE` |

`HEX_SIZE` 由 `map_data.hex_size` 注入，不在 `hexgrid.py` 里写死。

### 3.8 `render/camera.py`

| 属性 / 方法 | 说明 |
|---|---|
| 位置 | 世界坐标浮点（`cx`, `cy` = 相机中心） |
| 缩放 | `zoom`（像素 / 世界单位）；初始 zoom 使**每格边长约 40px**（对应 1600×1300 窗口下可见约 40×32 格） |
| `zoom_min` | 整张地图完整可见且包围盒较长边 ≈ `min(屏幕宽, 屏幕高) * 0.5` |
| `zoom_max` | 单格边长 200px |
| `world_to_screen(x, y)` / `screen_to_world(sx, sy)` | 变换 |
| `pan(dx, dy)` | 按屏幕像素平移 |
| `zoom_at(factor, sx, sy)` | 以屏幕锚点为不动点缩放，自动夹在 `[zoom_min, zoom_max]` |
| `on_resize(w, h)` | 重算视口，重夹 zoom |

### 3.9 `render/hex_renderer.py`

| 项 | 决定 |
|---|---|
| 绘制范围 | **只画视口内格子**（先算视口覆盖的 (col, row) 区间，再逐格绘制；不得全图遍历） |
| 单格绘制 | 平顶六边形多边形；填充 + 描边（颜色走 `config.py`） |
| 边界缝隙 | 相邻六边形共享边，描边重合；不得出现可见缝隙 |
| 脏标记 | 相机不动时不重绘静态层（可用背景 Surface 缓存整帧，或按帧重建但只遍历视口内格子；二者择一，实现侧决定） |

### 3.10 `app.py`

| 阶段 | 行为 |
|---|---|
| 启动 | `setup_logging()` → `install_sys_excepthook()` → `pygame.init()` → 建窗口 → 载地图 → 建相机 |
| 主循环 | 事件处理 → 更新相机 → 渲染 → `pygame.display.flip()` → `clock.tick(FPS)` |
| 事件 | 见 §3.11 |
| 退出 | `pygame.QUIT` / 关闭窗口 → `pygame.quit()` → 正常返回，进程退出码 0 |
| 异常 | 顶层 `try/except` → ERROR + traceback 入日志 + 尝试继续运行（若 pygame 已死则退出） |

### 3.11 交互（步骤01）

| 操作 | 行为 |
|---|---|
| 鼠标左键按下 + 拖拽 | 平移视口（按下位置为锚，按屏幕像素位移） |
| 滚轮上 / 下 | 以鼠标为锚点放大 / 缩小 |
| 窗口缩放 | 重算视口，zoom 自动重夹 |
| 关闭窗口 | 正常退出 |

### 3.12 日志接入

| 项 | 决定 |
|---|---|
| 引用 | `from shared.logging_setup import setup_logging, install_sys_excepthook` |
| 启动顺序 | `setup_logging()` → `install_sys_excepthook()` → `pygame.init()`（**不**调 `install_tk_excepthook`） |
| logger 命名 | `logging.getLogger("battle.xxx")`（如 `battle.app` / `battle.core.map_data` / `battle.render.camera`） |
| 降级 | `import shared.logging_setup` 失败 → 退回 `logging.basicConfig` 标准日志（格式与主游戏一致），**不静默吞异常** |

## 4. 边界与兼容

| 场景 | 处理 |
|---|---|
| `shared/` 目录当前不存在 | 本轮新建 |
| `battle/` 目录当前不存在 | 本轮新建 |
| `shared.logging_setup` 在 `python -m battle` 时不可 import | 降级为标准 logging + 终端提示；不阻断启动 |
| 地图 JSON 字段缺失（如无 `tiles`） | 视为空 tiles，正常加载 |
| 地图 JSON 文件不存在 / 损坏 | 弹窗提示 + ERROR 入日志 + 退出（进程退出码非 0） |
| 窗口尺寸小于 1 格 | zoom 走 `zoom_min` 夹取，不崩 |
| 用户缩放超过 `zoom_max` | 夹在 `zoom_max` |
| 窗口缩放后坐标越界 | 相机位置 clamp 在世界包围盒内 |
| 主游戏侧对 `game.config.logging_setup` 的旧 import | 由薄壳 re-export 兜住，**行为不变** |
| 主游戏侧对 `game.config.constants.LOG_DIR / LOG_ENABLED` 的引用 | 值不变（从 shared 导入），**行为不变** |
| 主游戏侧 PyInstaller 打包路径 | 沿用主游戏既有方案；`shared/logging_setup.py` 的路径反推只保证源码运行场景，打包场景留待主游戏侧单独处理 |
| 主游戏与 battle 同时写日志 | 共用 `userdata/logs/`，各自 session id，互不干扰 |
