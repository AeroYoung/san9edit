# 任务：更新 README.md 与 CHANGELOG.md（提示词优化版）

---

## 核心原则：文档分层

本项目文档分两层，**内容归属严格分层，不得越界**：

| 层 | 位置 | 承载内容 |
|---|---|---|
| 主游戏级 | 根目录 `README.md` | 主游戏整体：地图 / 面板 / 剧本 / 编辑 / 日志 / 主游戏级约定 |
| 战斗模块级 | `battle/docs/` 下各文档 | 战斗模块全部细节：地图规格 / 兵种表 / 命令系统 / 战斗规则 / 渲染 / 接口 / 阶段步骤 |

规则：
- 战斗模块的**任何细节**（字段、数值、规则、命令、渲染、接口、步骤）只写在 `battle/docs/` 里。
- 根目录 `README.md` 对战斗模块**只写引用**：一句定位 + 指向 `battle/docs/模块说明.md`，不展开任何细节。
- `CHANGELOG.md` 对战斗模块**只写一句话简述**，不列战斗模块内部改动条目。
- 战斗模块自己的变更，写在 `battle/docs/CHANGELOG.md`（若存在），不在根目录 CHANGELOG 展开。

# 任务一：更新 README.md

你是「README 维护者」。这份 README 的唯一服务对象是：**AI（如 DeepSeek 网页版）读取它，用来理解项目、整理需求、生成需求文档**。它不是给人看的介绍文，也不是营销文档。

## 最高优先级：判断每一段该不该写
每写 / 改一句话，先问四个问题：
1. 这能帮 AI 一次读懂项目吗？
2. 这能帮 AI 定位「雷区」和「契约」吗？
3. 这会不会稀释上下文、让关键信息不显眼？
4. **这条内容属于主游戏级还是战斗模块级？** 若属战斗模块级 → 不写进本 README，只写引用。

前三个问题里任何一个答不好 → 删 / 压 / 改。第四个问题答「战斗模块级」→ 移出本 README。

按以下优先级获取，不要凭空发挥：

## 阶段 D：生成打包脚本

写一个 **Python 脚本**（不是伪代码，可直接运行），要求：

### 硬性要求
- 放在**项目根目录**（脚本内部按判定模块决定扫描路径），用户直接 `python pack_for_review.py` 就能用
- 输出一个 **markdown 文档**（代码用 ```python 包裹，JSON 用 ```json 包裹）
- **自动分卷**：若单文档 > 300KB，自动拆成 `_01.txt / _02.txt ...`，每卷约 80–100KB
- 分卷时按 `### 文件名` 边界切，**不切断单个文件**
- 缺失文件不报错，正文标 `[缺] 路径`
- 脚本末尾打印输出文件路径 + 大小 + 上传提示

### 脚本内容要点
- `CODE_FILES` 列表：本次要看的所有代码文件（相对路径）
- `slice_*_json()` 函数：对每个 JSON 做截取（前 N 条 + 末尾 N 条 + 元数据）
- 缺失文件跳过并记录
- 自动判断单文件 vs 分卷
- 扫描路径按判定模块限定：主游戏不扫 `battle/`，战斗模块不扫 `game/`

用户运行脚本后，把生成的文件**贴回对话**。你不需要让用户手动选文件。

## 阶段 F：生成需求文档

需求文档是给**下游编码 AI** 的。写作原则：

### 定位
- 描述「**要什么**」，不描述「怎么改」
- **不指定**具体函数名 / 行号 / 代码片段
- **可以**列出涉及的模块 / 文件（帮下游 AI 定位）

### 必须包含的章节（顺序固定）

    0. 前置说明
       — 让下游 AI 读对应模块文档的哪些章节
         · 主游戏：README.md 的 §0 术语表 / §8.3 永久约束 等
         · 战斗模块：battle/docs/模块说明.md 的对应章节

    1. 背景问题
       — 为什么现在要做这件事，现在的痛点是什么

    2. 需求目标
       — 做到什么程度算完成

    3. 规则细节
       — 判定规则 / 默认值 / 状态转换，用表格不用长段落

    4. 边界与兼容
       — 老数据 / 老剧本 / 空值 / 冲突怎么处理

    5. 不要做的事
       — 防过度实现，明确列出「别动 X」「别加 Y」

    6. 约束
       — 引用对应模块文档已有的约定
         · 主游戏：Command 模式、日志格式、弹窗数据驱动…
         · 战斗模块：数据层与渲染层分离、配置集中、tick 模型…

    7. 验收清单
       — 可勾选的具体行为（启动后应该看到什么 / 点了什么会怎样）

    8. 完成后请提供什么
       — 让下游 AI 报告：改了哪些文件、测试结果、验收情况

### 落点规则（★ 硬性）

| 模块 | 需求文档路径 |
|---|---|
| 主游戏 | 根目录 `需求文档.md`（按轮次替换） |
| 战斗模块 | `battle/docs/步骤NN需求.md`（NN 为步骤号，不替换历史步骤） |
| 跨模块 | 主归属落点 + 另一侧只写接口引用 |

### 语言风格
- 面向 AI 读者，不用口语、不用营销词
- 用表格 / 清单，不用长段落
- 术语严格与对应模块文档一致，不自创
- 每一条改动都能追溯到某句用户需求或某段已确认结论

1. **不编造**：没在模块文档 / 代码 / 用户答复中出现的，不写进需求
